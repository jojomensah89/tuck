# Island reliability and usage refresh

Scope: notifications keep an active open island open, with a quiet pointer-transparent status strip and polite accessible announcement. No tab, focus, pin, drag or native hit geometry change is requested. Closed announcements and the HUD keep their existing queue and return rules. Open queued announcements drain without entering peek.

AI usage has a named 36px refresh icon. One pending UI request and a native busy guard coalesce repeated clicks. The new refresh_usage command requests installed-client refresh without enabling that source, rereads the existing local status file, and requests configured API spend refresh through the existing worker. Completion tickets wait for worker attempts, with a 90-second error timeout. Provider status remains authoritative: stale or error results do not become healthy values; previous readings survive request failure. No prompts or model turns are used. Four-card rings use 56px faces to fit the toolbar; two-card faces remain 72px and dense five-card faces remain 44px.

The settings gear uses secondary ink and a 24px optical box within its existing 36px target, with the existing rail focus and hover treatment. Expand-on-hover is removed from Settings following the user answer; normalization overrides legacy false values and runtime always uses the existing hover delay. Click, keyboard, pin, drag and fullscreen paths remain in place. Branding and model/audio/clipboard work are outside scope.
